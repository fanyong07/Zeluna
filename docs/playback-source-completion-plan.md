# 播放源全量可见与规则修复交接

## 背景
118 项审计清单不是 118 条可播线路：包含 13 爬虫适配器、20 正式采集站、80 候选和 5 旧兼容项。旧接口返回运行时发现结果，没有把未接入、停用条目交付给客户端，因此仅修改页面无法补齐清单。历史规则隔离检查不能将候选地址或 HTTP 200 作为播放成功。

## 目标与范围
- 每部作品显示当前注册清单，保留所有真实返回的独立线路，并解释未查询、未匹配、访问失败和未接入的区别。
- 快速播放不等待全部源扫描；完整扫描仍只调用已准入、已启用源。
- 对规则按失败位置修复，维持现有权限和可信媒体验证，不为凑数量伪造成功。
- 已授权本轮提交、推送、洛杉矶后端部署及 Android/Windows 新版交付；依次通过回归、精确 HEAD 门禁和产物核验。具体上线结果以部署凭据、发布 manifest 为准。
- 不替换用户已安装客户端，不新增规则域名权限、不永久启用未授权规则，不部署韩国常驻服务。

## 已实现
1. 快速和完整播放接口，在服务返回后补齐只读登记清单。补齐不进入播放缓存、不改变服务发现范围，不调用新适配器。
2. 清单身份独立于线路标签：同一适配器的 58 条线路仍全部保留，但源统计只计 1 个；不同分组同名源不合并。
3. 候选、停用、旧兼容项明确标注非查询状态；没有媒体 URL，不能发起播放或验证。未知/畸形库存标记不能提升为可播。
4. 客户端保留注册身份与状态，显示登记来源/已查询来源数量和安全的原因解释；不显示上游响应、鉴权头或原始报错。
5. 三类内容均使用同一可见性机制，不根据来源名称猜测影视/电影能力。

## 本机重查：真实能力与边界
- 正式、已启用、公开 HTTPS MacCMS 在来源面板提供“本机重查（本集）”；同一注册源只显示一个入口，所有返回线路仍保留。
- 点击时说明将向选定采集源发送作品名。本机直接完成搜索、详情解析和媒体探测；VPS 只返回绑定注册身份的静态协议描述，不转发该次源请求。
- 此次查询不持久化逐源路由。普通查询仍使用 VPS，“搜索全部线路”会取消旧本机任务并恢复普通发现；本机失败不暗中改用 VPS。
- 标题、已知年份、内容类别和集数均需匹配。动画电影按电影处理，来源名称不决定是否查影视剧/电影。媒体探测通过不等于已通过原生播放器首帧验收。
- 每源总预算 30 秒、请求预算 10 秒、最多 3 个并发媒体探测；切集、账号/服务设置变化、取消、超时、页面销毁后，不接受旧结果。
- 搜索端点必须公开 HTTPS、无用户名密码/查询参数/片段、443 端口；拒绝搜索跳转。候选和媒体子资源沿用既有公开地址与 TLS 安全验证，不执行下载脚本、不增补规则授权。
- 服务端专用爬虫、旧兼容接口、HTTP-only 源、候选/停用源不宣称支持本机查询。没有配置代理的直连仍可能受设备 VPN/TUN、运营商出口和来源风控影响，不能保证避开 IP 限制。

## 后续规则修复顺序
1. 域名变更：对历史出现跨域跳转的规则，先重新检查新域名的公开 DNS、TLS、页面和真实媒体。仅提议精确权限变更，不自动授权或执行新域名脚本。
2. 选择器/标题匹配：检查实际搜索和播放页，修复最小选择器或别名；番剧、电视剧、电影各至少两部，不按名字删类。
3. 拒绝访问/限流：降低并发、限次复测，比较两个出口；不得绕过验证码、登录、DRM或伪造授权。
4. TLS/网络错误：确认公开地址、正确域名和证书链；不得关闭 TLS 验证或允许私网。
5. 清理：未查询、未匹配、暂时超时不等于死源。删除只针对有重复、明确失效证据且备份可恢复的配置；新增删除/配置变更需按用户授权范围执行。

## 韩国 VPS 使用边界
入口可达不代表完整播放。在选择副后端前，同作品同集对比搜索、详情、清单、必要子清单/密钥/媒体段、解码和播放器首帧；检查并发资源后，只为证实有优势的源考虑补充节点。没有这些证据，不直接复制全部聚合，更不擅自部署媒体转发。

## 验收标准
- 本地当前登记清单：118 个唯一身份，80 个候选明确未接入；即使作品无结果，也能显示完整清单。
- 58 条同源线路不得折叠丢失；缓存返回/重复补齐不会新增假条目。
- 手机窄屏及桌面宽屏能够滚动看到最后一项，禁用项不能点播；源/线路统计不混淆。
- 所有可播判断保持既有媒体安全验证；显示登记项不能提升权限或媒体验证状态。
- 实际规则通过需要首帧、持续走时、暂停恢复和跳转，不仅是解析成功。

## 部署与待确认
- 本轮已获提交、推送、洛杉矶部署和 Android/Windows 新版交付授权；版本为 v1.2.0（内部 build 71），现有 v1.1.16 产物不覆盖。
- 后端需同步 `server/playback_inventory.py`、播放路由及现有 `data/maccms_candidates.json`；缺少候选数据不能声称清单完整。先核对实际生产代码及依赖，复制现有生产模块到候选目录，仅原子替换本功能的最小文件集并进行导入/合同验证。不同批次尚未上线的账户、字幕或数据库改动不得夹带，不覆盖环境变量、数据库或私人配置。
- 发布递增用户可见版本和 Android build，按精确 HEAD 通过门禁，再生成不可覆盖的产物和 manifest。部署保留回滚副本，核对服务健康和查询结果。
- 客户端/后端需协同交付。旧客户端仍能读取新增的不可播行，但新客户端的唯一源统计和详细状态需要新版本；单独更新客户端也无法创造旧后端从未返回的登记项。
- 新域名权限、韩国常驻服务、真实设备播放和具体规则修复，均单独记录验证及授权，当前不冒充完成。
