# Android 播放链路重构方案

## 背景

v1.2.4/v1.2.5 模拟器通过，用户真机仍不能播放。目标是《败犬女主太多了！》第一季第1集：Bangumi 464376 / TMDB TV 241535，禁止误测第二季。当前无 ADB 真机，因此不能声称手机根因完全确定。

本轮 quick 接口约2秒返回118个库存条目，只有6条带媒体候选，均 stale 且需要本机验证。库存数量不是可播数量。Python 默认 UA 被边缘层拒绝，实际 Dart/Mozilla UA 成功；这只是诊断客户端差异，不等于 App 根因。

## 修改前的失败回归

- 合法 iframe 内含媒体但 Kazumi 报无可播线路。
- 已授权 WebView 的脚本页面不进入嗅探。
- 只有音频时间轴也被当作首帧。
- 一个静默探测挡住另一条立即成功的线路，500ms 有界测试失败。
- 后端快速路径只试前4条，第5条能成功也不会尝试；独立失败回归已复现。修复后仍保持4路并发，候选预算12条。

记录在 `.codex_tmp/playback-refactor-red.log`、`.codex_tmp/playback-refactor-selection-red.log`；它们证明代码缺陷，不代替真机复现。

## 目标与范围

明确发现、解析、网络和解码证据；首个成功优先；全程可取消；失败能脱敏反馈。不换UI框架，不接别人私有后端，不自动扩大规则权限，不关闭 TLS/公网地址校验，不完整预下载视频，不改系统代理。

## 模块及规则

1. **来源发现**：保留 PlaybackDiscoveryController 的账户/上下文/集数隔离、后端与本机竞速。服务器证据不是本机解码证据，不另加重复缓存层。
2. **网页解析**：RuleMediaResolver 共用于 Kazumi/XBPQ，取代只匹配初始 HTML 的路径。直链 → 最多4页/深度2嵌套 → 已授权脚本嗅探；全程时间预算和取消。页面/媒体域名遵守原 manifest，跨域 iframe 去除凭据，不绕过验证码。媒体地址、实际引用页、过滤后 headers 一起交付并通过清单/key/首段验证。
3. **线路选择**：PlaybackRouteSelector 取代 quick 全量 Future.wait。最多3路并发，首个成功返回并取消剩余；未探测地址不标可播。完整库存仍使用已有 expanded stream。
4. **原生会话**：NativeVideoController.openRequest 收口传输准备、打开、所有权、播放许可和续播；沿用已有 PlaybackSessionController，避免第二套状态机。当前媒体解码截图是首帧证据，时间轴/宽高不是。图片只在内存中检查，不保存/上传。仅时间轴前进而无画面时尝试一次软件解码恢复。
5. **网络连接**：经现有公网校验后的 IPv4/IPv6 交错，250ms 错峰尝试；完成 TLS 才算胜者；失败/取消/迟到 socket 销毁。保持证书验证、SNI、DNS 绑定和 loopback 能力 URL 规则。
6. **诊断反馈**：传输层区分 HTTP/超时/TLS/连接/策略/清单，禁止异常原文和 URL。来源面板增加“复制播放诊断”，仅主动写本机剪贴板，不自动上传；使用已有脱敏规则与容量限制。只主动复制时读取应用版本、Android API/主ABI，不读取设备ID；探测失败原因也纳入报告。

参考固定源码记录见 `research/playback-reference-2026-10-30.md`。只借鉴职责和取消策略，独立实现；Anime4K 仅画质处理。

## 验收

| 场景 | 标准 |
| --- | --- |
| iframe/JS | 合法规则能解析；未授权、循环/深层、取消不越权或无限跑 |
| 快慢源 | 快源不等慢源，迟到结果不覆盖 |
| 双栈 | 首地址静默时备用接管；全部静默有截止；败方关闭 |
| 无解码画面 | 不误记 first_frame；有界恢复或明确失败 |
| 暂停/退出/切线 | 自动操作不抢走意图；过期打开/截图无效 |
| 诊断 | 不含秘密、URL和账号；仅主动复制 |
| API33实播 | 正确第一季，截图含动画，持续至少5秒 |
| 用户真机 | 待设备反馈；未通过不能声称已解决用户问题 |

## 发布、回退和待确认

测试、构建、精确 HEAD 门禁完成才创建新版本，不覆盖 v1.2.5。保留旧包用于对照。客户端修改没有后端部署必要时不动生产。发布说明注明真机未验证。用户手机型号、系统版本、失败阶段、代理/VPN/IPv6差异仍未知，应通过诊断补齐而不是继续猜测。
