# v1.2.3 播放恢复与发布交接

## 背景与目标

完整后端扫描常超过客户端 18–20 秒预算；渐进检索原先先等待完整扫描，才验证快查候选，造成已找到的线路迟迟不能播放。稀饭、月城的上游又改用了动态播放服务，旧静态规则无法取得媒体。

目标是先给出真实可用线路，慢源不能阻塞其它来源；保留完整来源库存、账号隔离、取消机制和域名安全边界。当前工作区此前积累的目录、界面和规则改动一并保留在本次最新版本中。

## 范围

- 客户端：快查候选验证与完整发现并行；合计最多四个后端候选验证；完整响应升级后的线路不会被旧候选的迟到结果覆盖。
- 后端：完整扫描默认等待最多 10 秒；需要时再用有限预算取得已有快查结果，总等待预算保持低于客户端超时。共享完整任务继续运行，不因单个请求超时/取消而丢失。
- 部分响应：`discovery_pending=true` 和 `X-Zeluna-Discovery: pending` 明确标记；客户端使用 `cacheState=partial`，不把它缓存成已完成完整检索。
- 规则：保留 MX 原生解析。稀饭、月城继续显示在库存中，但明确提示上游迁移并跳过自动检索，不冒充已恢复。
- 不扩大自定义规则授权、不改真实账号设置、不执行下载脚本，不绕过认证或验证码，不将网页当成媒体。

## 关键实现约束

- 快查不能降级完整缓存；部分结果不能成为完整扫描的负缓存。
- 超时必须屏蔽取消向共享任务传播；关闭服务仍需取消并回收后台任务。
- 所有线路保留来源身份和诊断信息，不把另一个来源改名冒充迁移来源。
- 后端部署只同步匹配的播放、聚合、缓存依赖集合，保留生产账号模块、环境变量、允许列表和数据库；部署前在隔离目录测试，备份后原子替换并保留回滚。
- 发布使用新版本 `1.2.3+74`，标签/显示名 `v1.2.3`，精确 Git HEAD 的 Quality Gates 成功后才正式打包。

## 已验证行为

- 确定性回归覆盖：完整扫描未结束时快查已验证可播；快查验证慢时完整线路先出现；重复来源不重复验线；权威版本不被迟到结果降级；部分结果可再次查全；并行验证保持上限。
- Windows 原生 MX 相邻两集均解码出图像，第二集预热命中。
- Windows 原生独播库电影《流浪地球2》、剧集《庆余年 第二季》相邻两集均解码出图像，下一集预热命中。
- 2026-10-26 本机对 17 个启用 MacCMS API 的同一样本查询中，14 个返回电影匹配。`detail` 与 `list` 未发现单独可用性差异，因此未臆测加入额外请求或放宽规则权限。

## 运行与验收

1. 运行 Flutter analyze、格式检查、全部测试，以及 Python 全部测试/静态检查/依赖审计。
2. 原生后端验证显式启用：`flutter test integration_test/backend_live_playback_test.dart -d windows --dart-define=BACKEND_LIVE_VALIDATION=true`。覆盖番剧、电影、剧集；默认测试与 CI 不访问上游。
3. 公开接口检查 `/api/v3/status`、快查、完整查源及再次查源；确认响应不超客户端预算，库存不缺项，候选和真实可播状态分离。
4. 精确 HEAD 门禁通过后，用仓库既有脚本生成 gate receipt、APK、完整 Windows ZIP 和 manifest；校验版本、内部 build、签名连续性、ZIP CRC、EXE、SHA-256。
5. 新建 GitHub Release，核对上传资产与本地校验和后发布，不覆盖旧版本。

## 待确认与限制

- 稀饭、月城需要独立评审和验证新的公开播放适配，当前版本没有宣称这两个来源已恢复。
- 本机没有 Android 设备/AVD；CI Android 模拟器启动验证与真实手机媒体播放是不同证据，发布说明必须区分。
- 上游站点会变化，已通过的样本不代表全片库、所有地区或长期稳定性。
- 本次执行证据、部署回执和安装包校验记录保存在工作区忽略目录，不提交签名媒体 URL、生产凭据或真实用户数据。
