# 弹弹play接入与播放恢复收尾（2026-09-09）

## 结论、背景与范围

用户要求检查最新提交并补齐未完成工作，随后明确以弹弹play接入为重点。本轮从远端 main 的 `5ab5f02d78029f18a4fd5fd8c4c31c5ffdb6284a` 建立 `codex/finish-latest-playback`；原本地 main 在 `ce8d3a7`，工作区原先干净。旧交接中的“服务未启用/未配置凭据”不能当成当前状态。

目标是打通自动显示、部分失败保留、有限恢复与明确诊断。范围仅包含最近播放启动/续播遗漏、弹幕仓库与控制器、服务端错误分类、相关测试和 Android 原生单测的 CI 接线。未修改凭据、部署、发布版本、签名、数据库或用户数据；未提交/推送。

## 本轮已实现

- 原生播放器轮询确认播放进度后，通知与流事件相同的首帧完成逻辑；解除加载态并触发已启用弹幕，避免“视频已开始但首帧事件漏报”。
- 单次原生续播定位挂起达到10秒后释放恢复阻塞，保留目标进度，不向同一挂起调用继续排队；旧调用结束不能污染新播放会话。
- 服务端在弹弹play降级来源增加 `error_code` 和 `retryable`。超时、网络中断、502/503等可恢复；授权失败、限流、未配置、禁用、未匹配和未知错误不自动重试。使用白名单用户文案，不返回上游错误正文或凭据。
- Flutter只识别明确的可恢复标记，不通过中文文案猜测错误。部分来源失败时保留该来源同集旧弹幕，同时更新其他成功来源；换集清理旧数据。
- HTTP错误和HTTP 200部分降级都使用有限重试；令牌读取、匿名回退、等待间隔、重试共同使用8秒总预算，不在每次请求重新计时。预算耗尽仍返回已获得的部分结果。
- Android原生单测接入Quality Gates的Android工作，在模拟器冒烟前执行；本地10项已通过，不等于远端CI已执行。
