# Zeluna v1.1.3 候选交付说明

## 背景与目标

在 Windows 实际界面验收中，发现“打开媒体 → 选择本地文件”把文件路径直接送入网络地址校验，导致本地视频被误判不可播放。本版本修复该入口，并保持 v1.1.2 已完成的无启动图体验与原生全屏实现。

## 范围与实现

- 统一规范化“打开媒体”和播放器内两个文件选择入口的媒体地址。
- 正确处理 Windows 盘符、UNC 共享路径、POSIX 路径以及文件名中的空格、中文、百分号和井号。
- 已有 URI 保持原样，不重复编码；这不代表新增对所有 URI 协议的播放支持。
- 不放宽网络媒体校验、不修改包名或签名、不升级依赖、不更改用户数据与服务端。
- 版本为 1.1.3+57；旧候选包、门禁与清单保持不变。

## 验收标准

1. 文件选择页面回归测试覆盖选择结果、播放器请求和媒体校验的完整边界；本地文件不需要 HTTP 探测。
2. Flutter 分析与全量测试通过；跳过项单列，不计作通过。
3. 精确提交的 Quality Gates 全绿，产物版本、Git SHA、门禁与哈希一致。
4. 使用无敏感内容的测试视频，从实际文件选择器进入播放，确认首帧、时间推进与暂停恢复。
5. 分别验收普通窗口和最大化窗口的全屏按钮、F/Esc 与退出后窗口恢复；受前台保护拒绝的输入不计作通过。
6. 正式 Android 发布仍须受保护生产签名、原升级身份确认及真实设备覆盖升级验收。

## 风险、回滚与待确认

- 本文是候选说明，不表示已经公开发布；运行结果记录在对应 SHA 的本地交付证据中。
- Android 原签名和真实设备、弹弹play服务器凭据仍需独立满足，不以 Debug 签名、模拟测试或仅 Windows 包替代整套交付。
- 本版本仅更改客户端，不为无后端差异的提交重复重启生产服务。
- 客户端回退应使用上一份不可变安装包；不得清空用户数据、覆盖旧包或复用已交付版本号。
