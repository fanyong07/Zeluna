# 安卓番剧资料与播放网络分离（2026-11-03）

## 背景与目标
用户实装 v1.2.8：关闭 VPN 后影视剧/电影正常，但番剧封面不显示、详情慢；开启 VPN 后资料恢复，播放线路却大量失败。目标是资料不再依赖手机直连 Bangumi，不把所有视频改为服务器转发，并减少详情等待和无关重算。

## 已复现与边界
- 回归测试重现：后端已返回详情/选集，只要可选的角色、人员等请求未完成，`CatalogController.detail` 就不返回，也不开始预热。
- 原生 PosterArt 直接使用 Bangumi 图片站；只有网页端有同源图片兜底。
- 规则 HTTP 客户端不接受 VPN 的合成 DNS 答案，而部分官方媒体客户端接受；仅 HTTPS 域名的安全兼容存在缺口。
- 开发机有无显式代理访问样本均成功，不能替代用户手机 VPN 开关对照。代理出口/IP限制和明文源的兼容仍未在用户实机证实。

## 方案与安全规则
1. 详情正文和选集先返回；可选补充资料后台完善，同一作品的并发读合并，账号/设置/清缓存后旧结果失效。
2. 详情补充不再重算整个首页推荐列表，不重复发送详情页预热。
3. 启用后端时，番剧筛选/日历优先已有公开资料接口。服务端限量合并缓存公开查询；429保留，不借直连绕过限流。
4. 新增公开番剧图片缓存，仅接受固定 Bangumi 域名的封面/角色/人物图片路径。校验每个重定向、公共IP、TLS、响应类型和文件头；2 MiB单图，32 MiB/256项内存缓存，6并发/32排队。禁止认证头/Cookie透传，禁止任意网址/视频代理。
5. 客户端只将 Bangumi 图片交给当前已配置后端；关闭后端后不暗中转发，自建后端沿用其配置。影视剧/电影图片和视频传输保持原链路。
6. 规则和原生媒体允许HTTPS主机名使用VPN合成DNS，仍验证原始主机名的TLS证书。不放行内网、直接IP、明文合成DNS，不更改用户VPN和系统网络设置。

## 验收
- 单元回归覆盖详情不阻塞、合并请求、晚到资料更新UI、账号/缓存失效、图片路由、限流和网络边界。
- 服务端验证缓存去重、过期、取消、重定向、非图片、过大内容、公共资料无凭据。
- `integration_test/catalog_network_live_test.dart`：禁用客户端直连元数据，真实后端查询/选集和真实图片解码必须成功；不注入媒体，不更改设备VPN。
- 发新版必须使用递增的版本和build、精确HEAD Quality Gates、签名与manifest核验。不能覆盖v1.2.8。

## 待确认
用户手机无VPN/有VPN两组网络及滚动流畅度，未连接实机，不能宣称全线路恢复或量化帧率提升。实时验证结果放入独立发布证据，不把导入成功或HTTP 200当解码成功。

## 本轮补充验证
- 安卓API33模拟器：同时阻断测试内的客户端直连Bangumi资料和图片请求，真实后端列表约2730ms，详情约610ms，12集，封面解码成功；不是用户实机网络时延保证。
- 下载进度导致详情头图重建的回归已先红后绿；详情只订阅本作品的资料、收藏、追番和播放历史。
- HTTP连接取消现在遵循SocketException契约，可被正常请求错误处理捕获。集成测试必须在创建请求的同一错误Zone内清理，避免测试结束后跨Zone接收未完成Future的错误；不能通过屏蔽日志假通过。
