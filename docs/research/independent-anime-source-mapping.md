# 独立动漫源站映射研究

## 0. 主线实施与验证补记（2026-09-13）

本节是主代理在研究收尾后的实际实现与验证结果；下文带“本侧”的只读结果指背景研究阶段，不覆盖本节更新。

### 完成范围

- 本地新增 `crawler.xifan`，复用 `HtmlDirectAnimeScraper` 直接访问稀饭原站，不调用 AniCh 搜索、详情或取流接口。只注册能力，不修改部署环境的启用列表。
- 保留原有全部 provider、原 AniCh 适配器及返回全量线路的逻辑；未删除、禁用或截断既有来源。不能确认原站的线路继续通过原接入兜底，尚未完成全部线路去聚合化。
- `player_aaaa` 只读取本集 `url`，支持嵌套 JSON 与末尾分号；不再把 `url_next` 和广告链接误当本集线路。删除错集候选不等于删除来源。
- 单个播放页请求失败不会丢弃其他播放组的成功结果；新来源的线路身份按原分组编号生成，部分组缺集不会让其他组改号。外站播放页链接不作为原站页面跟进。
- 原站实测会提示“搜索时间间隔为3秒”；同适配器串行请求并在上次响应后至少等待 4.2 秒，成功搜索元数据缓存 60 秒，最多 64 个关键词。限流页面不记作无片源，失败不写入该缓存。搜索预算 16 秒，精确匹配成功即停止额外别名请求。

## 1. 结论与不可回退的约束

本节至第 8 节为只读背景研究记录（主线随后实施结果见第 0 节），核验日期为 **2026-09-13（Asia/Hong_Kong）**。目标是为 Zeluna **增量接入独立原站**提供证据，不是将现有聚合线路一次性替换掉。

- **保留用户要求的现有约 58 条线路，AniCh 原线路继续作为兜底。** 找不到原站、未建立标签映射、一次访问失败或超时，都不是删除、隐藏或批量禁用旧线路的依据。
- **稀饭三个目标主机已获得原站页面证据**：`apn.moedot.net`、`play.xfvod.pro`、`dl.playxf.top` 分别出现在 `dm1.xfdm.pro` 同一作品的三个播放页的 `player_aaaa.url` 字段中。[F3][F4][F5][F6]
- **XGCartoon 的原站入口可以确认，目标 CDN 的映射目前是项目代码证据**；本轮原站页面及其公开脚本没有补齐 `xgct-video.vzcdn.net` 的当前使用证据。不能把代码中的常量当成此次媒体直连验收。[X1][X2][X3][X4][R3]
- **GiriGiri 的发布页与内容站对应关系可以确认**，但 `love.girigirilove.net` 与当前播放链路的对应关系尚未闭环。本轮实际播放页的公开编码字段解析后，主机为另一个域名 `giri.girigirilove.top`。[G1][G2][G4][G5][G6]
- 旧标签中，项目适配器明确将 `age` 命名为 AGE 并指向 `www.agedm.io`；`heibai`、`aniopen`、`yhdm-cn` 在本轮检查范围内只有旧标签清单，未找到具体站点映射。**完整 `xf → xifan` 标签族仍无配置证据，不得自动重命名或合并；第 0 节已补充 `xf-3`、`xf-3-2` 特定样本的精确对应。**[R1][R2][R4]
- 背景研究阶段 **0 条完成媒体直连可播验收、0 条完成生产出口验证**（主线媒体实测见第 0 节）。可访问页面、页面内存在地址、某域名被网站使用，均不等于媒体当前可播、覆盖足够或允许第三方聚合。

用户提供的“约 58 条”是当前保留要求，不是本侧实测数量。旧聚合计划以“52 个标签”为标题，但前轮清单核对实际为 51 个条目；这是历史材料，不得用它把当前线路基线降为 51 或 52。[R1]

- 详情中 `a.goto-chapter[href]` 的自然链接指向 `/user/page_direct`，携带公开内容标识 `cartoon_id`、`chapter_id`；本次跟随该链接和原站 302，最终到达 `www.twxgct.com/video/{slug}/{chapter}.html`。没有登录或手工构造绕过路径。[X2][X3]
- 当前视频文档有 iframe 元素，但静态 HTML 中没有 `src`；所引用的原站公开 `chapter.min.js` 中出现 `pframe.xgcartoon.com`。这仅证明脚本包含该播放器域名关联，不证明本次已加载播放器或目标 CDN。[X3][X4]
- 精确目标 `xgct-video.vzcdn.net` 只在本轮读取的项目适配器中得到明确映射，不是由此次原站播放器／媒体响应确认。[R3]

按主线后续要求，**停止该站实现细节扩展，不提出本轮代码变更，也不将旧线路移除。**

### 4.4 AGE：项目映射明确，现场异常待复测

`AgeScraper` 明确设置 `_name='age'` 和 `BASE_URL='https://www.agedm.io'`，代码中搜索为 `/search?query={关键词}`，详情为 `/detail/{id}`，剧集为 `/play/{id}/{线路}/{集}/`。[R4]

本次 MCP 直接读取首页得到 `Bad gateway 502!`，因此 **这些路径目前是代码证据，不是本轮成功访问结果**。只记录入口异常待复测，不从一次失败推导 AGE 永久失效，更不推导旧聚合 `age` 线路同时失效。[A1]

## 6. 保留策略：区分页面直访、聚合保留与异常复测

## 7. 交接与验收边界

后续代码修复、端到端样本、覆盖率和回归归主代理负责，本侧不重复执行。研究交接要求如下：

1. **增量接入**：保留原有 route/provider 标识和 AniCh 兜底；新增 `xifan` 不自动迁移、覆盖或删除 `xf` 等旧标签。
2. **沿原站实时发现**：搜索／详情／选集产生新鲜的原站播放页，再读取公开播放器数据；不硬编码本文的作品编号或媒体资源，不使用历史采样 URL。
3. **不绕过验证**：某一入口要求验证码、登录或权限时显式报告该路径受限；不把其他隐藏接口当作绕过手段。
4. **不凭数量冒充覆盖**：同一原站三组线路不代表三个独立来源；媒体域名、标签数、原站数和可用线路数分开统计。
5. **以不缩减体验为验收条件**：主代理先记录当前约 58 条线路的实际基线；未知映射、单次超时不能被过滤掉。只有明确的同内容／同集数可用替代经过验证后，才讨论逐步降低旧路径依赖，不据本研究删除旧线路。
6. **通过后再声明**：端到端可播、生产出口可用、回归保持线路数量和生产启用，必须分别有主代理验证结果；本研究没有这些结论，不能宣称“全脱离 AniCh”。

### 尚未确认

- 本侧独立核验的 `dm1` 搜索结果结构，以及后续是否稳定触发验证。

- 西瓜当前链路是否仍实际使用 `xgct-video.vzcdn.net`；本轮按要求不继续扩展。
- 站点服务条款、内容授权及第三方聚合许可。本轮没有获得授权结论。
