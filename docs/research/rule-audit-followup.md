# 线路显示与已安装规则复查

## 完成结果

- 实际安装记录：**64 → 55 条**；启用记录：**27 → 18 条**。已卸载 9 条当前不可用配置，保存了 Windows DPAPI 加密、解密回验通过的恢复备份。
- **8 个安装 ID** 的媒体样本在至少一个服务器出口实际解码出视频帧，覆盖 5 组站点/配置；不是 8 个独立站，也不是客户端全部可播证明。
- **47 条保留待复核**：不能把动态嗅探未完成、权限拦截、某两部样本没命中或一次网络失败当成死源。没有把这 47 条标成“播放通过”。
- 修复主分类误过滤、完整后端阻塞规则发布、前 8 条截断、相同 URL 不同线路身份被合并、部分失败线路消失、手机页只显示前 4 条，以及中断扫描被错误标记完成。
- 当前源代码已修改并测试，但**尚未打包更新已安装客户端、未部署后端、未提交或推送**。因此现用旧客户端不会自动获得代码修复。

## 背景、目标与边界

用户要求解释附录 A 的“未取得样本”、完整展示线路，并对全部已安装规则跨番剧/电视剧/电影测试后谨慎清理。
测试环境是洛杉矶生产服务器的隔离审计进程、韩国 VPS 临时快照环境，以及 Windows 当前安装规则的真实 Dart/jsf 解析运行时。
测试时间详见配套 JSON 的 UTC 时间戳（本地为 UTC+8）。本次没有向韩国 VPS 安装常驻后端、数据库或浏览器。

每条规则不论原名称或主分类，均安排《葬送的芙莉莲》《鬼灭之刃》《庆余年》《狂飙》《流浪地球》《铃芽之旅》六个样本。
56 个非 Drpy 安装 ID 执行双出口静态/原生公开协议搜索；8 个 Drpy 安装 ID 另外用应用真实受限 jsf 运行时执行六样本（等价配置复用任务）。两条特殊内容规则也补做了相同主流作品查询，未展示/导出其非目标内容。

服务器验证只读取有界的公开媒体字节：HLS 清单/首段/必要初始化与普通 AES-128 密钥在内存处理，解码器禁止自主网络访问；无登录、验证码绕过或 DRM 解密。最多四个媒体候选/样本播放页，不能当全部线路逐一长播。
洛杉矶第一版临时 FFmpeg 对合成 TS 也崩溃，故其初次“解码失败”作废；改用隔离 PyAV，合成样本自测通过后重新跑完。韩国使用已有 FFmpeg。未向生产 venv 安装依赖。

## 为什么 118 项不是播放时的 118 条线路

118 = 13 爬虫 + 20 正式 MacCMS + 80 待晋级候选 + 5 旧 TVBox 兼容接口。
生产启用的是 9 个 provider：MacCMS 聚合及 8 爬虫；正式 MacCMS 17 启用、3 隔离。候选登记不代表已启用。
一部作品只会从已启用且匹配到该作品/本集的来源取得真实线路。没有匹配、缺集、禁用或被限制的来源必须显示状态，但不能伪造成播放地址。

上一轮 LA 83 项、韩国 86 项未返回样本线路。针对双方合计需要复核的 API 接口，本轮逐项直接诊断 77 项（爬虫保留原适配器证据）：

|---|---:|---:|---|
| 域名解析失败 | 32 | 32 | 需按具体错误复核，不凭这一轮整体删除 |
| 连接/TLS/协议等传输失败 | 14 | 14 | 需按具体错误复核，不凭这一轮整体删除 |

## 实际修复与安全规则

1. 用显式多分类能力参与检索，主分类/名称只负责展示；旧未声明规则保留原分类，不把所有规则盲目开放到全部分类。
2. 爱看机器人、青空次元已获三分类样本解码证据，内置声明改为三分类。没有改变网络域名、Cookie、脚本或信任级别；第三方规则权限变更仍需按新摘要重新批准。
3. 快速首播与完整查线分开。完整后端搜索和规则流并行发布；来源失败不擦掉已返回线路。
4. TVBox/CSP 不再限制前 8 个播放组；爱看机器人不再限制前 8 个候选。完整验证用有界并发，TVBox/爱看机器人遇到截止时间保留已经枚举的未验证地址，但不可点击播放。
5. TVBox 同 URL 的不同线路保留独立 ID，快速和完整阶段身份一致；其他静态引擎用路线序号区别同 URL 路线。
6. 手机竖屏页改成可滚动的完整线路列表，不再只露前 4 条；不可用/受限条目有状态且不可误点播放。
7. 扫描中断、出错或超时不再被视为永久完成，重新打开可以重试。
8. 增加卸载记录，防止已删除的内置推荐规则在下次账号加载时自动重装；用户主动重新安装仍有效。
