# Zeluna v1.0.0+39 稳定性更新交接

## 背景

本更新接续 `handoff-2026-08-23-changes.md`。原工作区包含尚未提交的
kanju1 播放线路安全、诊断分类和候选探针改动；项目评审中的稳定性与发布
可信度修正尚未形成闭环。

## 目标

在不引入高负担装饰和动画依赖的前提下，完成一版可验证、可追溯、可回滚
的客户端与服务端更新，并交付 Android APK、Windows ZIP、发布清单、VPS
部署证据和 GitHub exact-HEAD CI 证据。

## 范围

做：

- 播放 URL 安全过滤、headers 透传、缓存过滤、准确诊断和 MacCMS 候选探针。
- 首页旧缓存立即返回与独立后台数据库会话。
- 推荐成熟度、特征权重、first-frame 语义和跨 provider 作品身份修正。
- Android 横屏完整控制与多尺寸回归。
- 版本、Git SHA、CI run 和制品 SHA-256 的强绑定发布门禁。
- 临时图片清理、控制器增长防线、测试、打包、部署与推送。

不做：

- 不接入 React 组件库、Anime.js 或新的重动画框架；Flutter 原生轻量布局已能
  达到本版目标。
- 不复制外部站点视觉、不导入来源不明的播放规则、不绕过站点访问控制。
- 不更换现有框架、状态管理或整体视觉语言。

## 关键规则

- 旧缓存可立即服务时，请求不得等待第三方元数据刷新。
- 后台任务不得持有 request-scoped SQLAlchemy session/repository。
- 横屏最小 568x320 必须保留核心播放控制且无溢出。
- 只有 GitHub `Quality Gates` 成功 SHA 与本地 HEAD 完全一致才能打包。
- 同一版本号不得对应不同 Git SHA；制品和清单不得覆盖。
- VPS 必须先隔离候选验证、保留数据库与回滚点，再原子部署。

## 实现思路

目录刷新以每个媒体类型的 single-flight 后台任务运行，并由 session factory
创建独立会话。推荐模型只用 distinct work 判断成熟度，并降低平台/年份等弱
特征。横屏用紧凑完整控制行，避免为了“华丽”引入新依赖。发布脚本通过 CI
回执验证 exact HEAD，再生成带完整哈希的不可变清单。

## 验收标准

- Flutter 全量测试、静态分析、格式检查通过。
- 服务端全量 pytest、Ruff、compileall 通过。
- 568x320 至 854x384 横屏 Widget 测试无溢出，CI 模拟器旋转后应用仍存活。
- GitHub exact-HEAD `Quality Gates` 全部成功。
- `release` 中存在 v1.0.0+39 APK、Windows ZIP、SHA-256 sidecar 和 manifest。
- APK 非 debuggable、签名连续性已核对；Windows ZIP 可启动。
- VPS 隔离候选测试通过，生产服务、数据库与公开健康接口部署前后正常。

## 待确认事项

- 第三方采集站可用性随时间与机房出口变化，部署验收只代表本次时间点。
