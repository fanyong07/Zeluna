## 结论

1. **本轮应追的是 AniCh 标签背后的目录源站，不是另外增加几个 MacCMS 站点来代替。** 已将附件 JSON 的全部 52 个标识与项目对照；另保留项目后续样本中的 `ccw`、`dm-xhs`。任何未知归属都不是删源依据。

### 1.2 报告中必须降低确信程度的推论

- “后缀 k/s/i/w/c 就是固定仓位”：JSON 的 `fk`、`xgk` 指向 `fileproxy.scsusercontent.cn`，并不是所有 `k` 都指向快手。原报告 family 表还把 `fk/fok` 合写在快手列，和自身逐项数据冲突。后缀只能是调查线索。

- “32 个非代理就是真直连”：`bf` 的 `player.91ju.cc` 可能是播放器脚本入口。项目已将这一域名的 PHP 包装入口作为需进一步识别的例子；不应直接当视频或站方提供的搜索 API。
- “已经识别 14 个原站”“独立上游约 20 多个”：附件没有足够的目录映射证据或完整可复算的同源判定规则，不可用来合并删除线路。

### 3.2 旧的 XF 影视代码不是已完成接入

`CommonVodScraper` 注释声称 XF 电视剧和电影，但实现对媒体主机 `play.xfvod.pro:8088` 拼接 `/search`，结果固定 `type=tv`；本轮没有源站公开 API/搜索表单支持这一拼法。`aggregate.vod` 虽注册在兼容层，却未加入稳定作品 `discover_source_matches` 的候选任务。隔离控制调用只启用该 provider，movie 发现时 `_vod.search` 调用数为 0。

因此不能回答“项目里已经写了 XF 影视，所以已经接好”。这部分应由真实内容站搜索/详情适配替代，不能修一个注释就算完成。

### 3.3 电影与电视剧元数据并不需要重建

本项目本来有 `tmdb:movie`、`tmdb:tv` 和 Bangumi 稳定作品 ID。附件报告对 AniCh“缺影视元数据”的描述不应被照搬成 Zeluna 也缺同一能力。Zeluna 要补的是**来源发现能力、类型/版本/分集匹配和线路解析**，不是另起一套电影/电视剧页面或复制 ZIP 的番剧库。

## 4. ZIP 结论

静态审计已完成：14 个文件，11 个 Python 文件仅作语法解析，没有执行或导入。15 个不同种子标识、8 个具体解析器实现、默认装配 4 个；并不包含 58 条 AniCh 标签到原站的逐条映射。

完整种子标识：`yhdmm、dmttang、yhdmone、girigirilove、yhnime、yinghuadh、yhdm365、yh_dongman、iyinghua、yhdmz2、yhpdm、yinghua_us、nanhuyt、dlidli、xfvod`。另有 wmxz 的发现正则，但无对应解析器；重复的 girigirilove 字典键不算新站。

不能整套替换：默认元数据搜索仍只番剧；未知响应被错误标为可播；存在关闭证书校验、自动读取 Cookie、完整 URL 日志、循环导入/正则不匹配和默认启发式删除 HLS 分片等风险。`dlidli` 种子不能仅按名称等同于主线核实的“打驴”。可复用的是经过隔离测试的解析思路，不是默认启用表和安全策略。

完整依据见 `anich-provided-zip-audit-2026-09-13.md`；原 ZIP 哈希未变，未运行其命令、域名轮换、Cookie 导入或转存逻辑。

## 5. 建议的实施顺序与验收标准

1. **已修本地来源规则，接下来是部署后端与客户端验收**：xifan/xgcartoon/girigiri/yhdmm。已有真实电影的后端发现证据；仍须在获准部署后，从 TMDB 动画电影页面验证媒体和首帧，不能把后端元数据命中说成设备可播。
2. **综合真人影视重点追 bf→91ju/播剧候选**：需要第一方的电影和电视剧详情及同集播放对应；不要绕 403，也不能等同项目中的暴风 MacCMS。已经能确定范围但无法本机访问时保留待目标出口审核。
3. **为 lm/路漫漫、dl/打驴补独立目录**：确认站方现行入口/搜索/详情后再接入；已证实动画电影就接电影范围，未证实真人电视剧就不伪报。仍保留全部旧线路。
4. **剩余代理/对象存储标签继续作为 AniCh 兜底**：记录原标签和交付方式，不把共享 CDN 当成搜索站。只有同作品同集的第一方来源证据充分，才挂接独立 provider；没有证据不重命名、不隐藏、不合并。
5. **ZIP 仅移植经过审查的解析组件**：使用本项目现有 MediaProvider、稳定身份、类型校验、网络安全与候选审核门；不执行整套 pipeline，不照搬所有启用项，不以“有文件”当“已可用”。

每个原站至少验收：真实电影、电视剧（如有）、番剧 → 年份/季数/版本 → 指定第 1 集和中间集 → 实际媒体清单/首片段/必要密钥（如有）→ 首帧 → Android/Windows。类别无资源时如实标注。原站直访调用不得出现 AniCh；未知源继续保留旧线路且不能减少现有可用范围。来源晋级、部署与安装包交付仍遵循项目原有审核/版本规则。
