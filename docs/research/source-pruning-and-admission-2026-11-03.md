# 来源精简与实际接入修复（2026-11-03）

## 背景与目标

用户明确要求删除无用来源、不要新增备份，并保留 AniCh、Kazumi 和此前提供的规则订阅。此前“登记”“拉取”“可执行”“已解码”混用，不能再用登记数量代表可播放来源。

## 范围与清理规则

- 删除 74 个未准入候选的数据文件、2 个隔离 MacCMS 登记（风车、暴风）、2 个停用爬虫登记（706、dbku）以及 5 个重复/停用 TVBox 端点。118 个登记项减为 35。
- 不新增删源备份，不改账号、用户规则、凭据、数据库结构。保留通用 TVBox/DBKU 解析能力，用户独立导入的规则不是同一个停用后端登记。
- 旧播放缓存不能把删除的来源重新加入响应；保留当前登记来源的真实线路与客户端复验候选。35 是登记数，不是每部作品保证可播的来源数。
- 不把未准入来源说成经过实测永久关闭，不删除用户指定保留的规则库。

## 已复现的接入错误与修复

### AniCh

同一服务器直查《败犬女主太多了！》返回正常，但部分日文/无结果查询返回 HTTP 500。旧传输层将查询错误升级为整个域名冷却，其他作品的正常检索、取流也被阻断。现在查询级 400/404/422/500 快速返回当前查询错误，不污染域名健康；连接故障、限流和服务不可用仍走原有受限退避。空的成功 protobuf 搜索结果按空列表处理。

另外，只要别的来源提供足够线路，完整结果缓存就可能把 AniCh 的暂时搜索错误保留 6 小时。现对临时失败采用 60 秒恢复窗口，继续立即提供好线路，复用已有单任务后台刷新，确认无匹配和不支持的内容类型仍使用正常缓存。

### Kazumi

- `useWebview` 表示网页解析，不等于验证码。Android/Windows 已有受限 WebView 解析器，旧准入判断却把这类规则全部排除。现在正常网页解析可参与执行，显式 CAPTCHA 仍需人工验证。
- `antiCrawlerConfig` 存在但 `enabled=false` 不再误判为防爬挑战。
- 新版 API 搜索/章节字段以前只保存而不执行。补全公开 GET 搜索、JSONPath 子节点/数组读取、XPath 详情、分隔和嵌套章节。所有请求仍经过域名、重定向、响应大小、取消和媒体验证边界。
- 不执行脚本型 JSONPath，不放开私密请求头或认证接口，不自动扩大已批准的域名权限；规则权限改变仍需重新批准。
- 内置离线目录同步为官方当前索引 18 条，而非陈旧目录；索引未列出的历史文件不自动启用。

## 仓库核对
